# Readiness rubric (8 criteria, 0-5 each, max 40)

Anchors: **0** no evidence · **1** mentioned or started · **3** partly works, gaps obvious · **5** complete and proven. Use 2 and 4 between anchors. No evidence = 0.

| # | Criterion | 0 | 3 | 5 |
|---|-----------|---|---|---|
| 1 | Product clarity | cannot tell who it is for | user and problem clear, pitch missing | one-sentence pitch, user, problem, differentiator |
| 2 | Working state | does not run | main path works, rough edges | full path runs from clean checkout, demo-able |
| 3 | Code and architecture | one tangled file, dead code | structured, some debt | clear modules, no obvious debt, easy to hand over |
| 4 | Tests and docs | none | README plus some tests or docs | setup docs, tests on the core, changelog |
| 5 | Security hygiene | secrets in repo | no leaks, basics partly missing | gate clean, auth and validation in place |
| 6 | UX and design | unusable | usable, inconsistent | consistent, responsive, polished |
| 7 | Market evidence | no users, no research | research or interest, no commitments | pilots, paying users or signed intent |
| 8 | Sales assets | nothing | demo or deck, no pricing | demo, deck, pricing, legal basics |

Cap: while a critical security finding is open, criterion 5 is at most 1.

## Labels

| Total | Label | Meaning |
|-------|-------|---------|
| 0-10 | concept | idea, maybe sketches |
| 11-20 | prototype | proves a point, not usable by others |
| 21-30 | MVP / demo | usable and showable, gaps for paying users |
| 31-36 | pre-sale | can be shown to a buyer with caveats |
| 37-40 | sale-ready | package a buyer can evaluate without you |
